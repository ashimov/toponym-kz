# Топонимы Казахстана

Интерактивная карта топонимов Казахстана: происхождение названий, исторические формы с датами и источниками, языковые пласты. Данные хранятся как текстовые карточки в Git, карта собирается из них автоматически.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # статика в dist/, можно выложить на любой хостинг
```

Перед сборкой карточки проверяются по схеме (`npm run validate`).

## Как добавить топоним

1. Создай файл `data/toponyms/<id>.yaml`. `id` — латинский слаг, совпадает с именем файла.
2. Заполни по образцу, например [data/toponyms/atyrau.yaml](data/toponyms/atyrau.yaml). Схема всех полей: [data/schema.json](data/schema.json).
3. Если ссылаешься на новую книгу, добавь её в [data/sources.yaml](data/sources.yaml) и используй её `id`.
4. Запусти `npm run validate`. Скрипт укажет на ошибки: неизвестный источник, координаты вне Казахстана, опечатки в полях.
5. `npm run dev` и посмотри карточку на карте.

Минимальная карточка:

```yaml
id: aktobe
names:
  kk_cyr: Ақтөбе
  kk_lat: Aqtóbe
  ru: Актобе
  en: Aktobe
type: city            # city | town | village | river | lake | sea | mountain | range | desert | steppe | region | site | other
coords: [50.2839, 57.1670]   # широта, долгота
region: KZ-15         # код области ISO 3166-2
layer: turkic         # turkic | mongolic | iranian | arabic | russian | soviet | hybrid | substrate | unknown
status: draft         # draft | reviewed | published
etymology:
  - gloss: «белый холм»
    language: kazakh
    analysis: Ақ «белый» + төбе «холм».
    reliability: high # high | medium | low | folk | rejected
    source: konkashpaev-1963
historical_forms:
  - form: Актюбинск
    script: cyrillic
    language: russian
    from: 1891
    to: 1999
    official: true
sources: [konkashpaev-1963]
links:
  wikidata: Q184042
```

### Принципы заполнения

- **Этимология — это список гипотез, а не одна истина.** У каждой гипотезы своя оценка надёжности: `high` — консенсус словарей, `medium` — одна авторитетная версия, `low` — гипотеза, `folk` — народная этимология, `rejected` — опровергнута. Народные версии тоже фиксируем: их полезно показывать как отвергнутые.
- **Каждое утверждение с источником.** Поле `source` — это `id` из `sources.yaml`. Страницу указывай в `note`.
- **Исторические формы с датами.** `from`/`to` — период употребления, `attested` — год конкретной фиксации в источнике. `official: true` означает официальное название в этот период. Именно эти поля двигают ползунок времени на карте.
- **Форма как в источнике.** Арабицу, рунику, греческий пишем в оригинальной графике и указываем `script`.
- **Пишем «строка: текст» в кавычках.** В YAML двоеточие с пробелом внутри значения ломает файл: `note: "Памятник: строка 37"`.
- Все текущие карточки имеют статус `draft`: этимологии и даты в них — черновики, которые нужно сверить по словарям, прежде чем менять статус на `reviewed`.

## Исторические фотографии

В карточке города есть галерея «Фотографии по годам». Снимки берутся с Викисклада (Wikimedia Commons): там они свободно лицензированы, у каждого есть дата, автор и ссылка на страницу с описанием. Сайт не обращается к Викискладу вживую: метаданные выкачиваются заранее и лежат в `public/data/photos/<id>.json`, а сами картинки подгружаются с серверов Wikimedia.

Как подключить фотографии к карточке:

1. Найди на Викискладе категорию города, например `Category:History of Semey` или `Category:Almaty by year`. Проверить наличие категорий: `node scripts/commons-search.mjs --category "History of Taraz"`.
2. Впиши её в карточку:
   ```yaml
   commons_categories:
     - History of Semey
   ```
3. Лучшие снимки можно закрепить вручную, они показываются первыми и помечены звёздочкой:
   ```yaml
   media:
     - file: "Ascension Cathedral 1913.jpg"   # имя файла на Викискладе без File:
       year: 1913
       caption: Вознесенский собор, 1913 г.
   ```
4. Выкачай метаданные: `npm run photos -- semey` (одна карточка), `npm run photos` (новые), `npm run photos -- --all` (обновить всё).

Wikimedia требует указать контакт в User-Agent, иначе отвечает ошибкой 429. Перед запуском задай его: `COMMONS_CONTACT="https://github.com/<логин>/toponym-kz" npm run photos`.

Галерея связана с ползунком года: снимки в пределах пяти лет от выбранного года подсвечены, ближайший обведён красным. В просмотре снимка есть ссылка «карта в 1913», которая переставляет ползунок на год фотографии. Скрипт берёт только снимки до 1991 года: порог задаётся параметром `maxYear` в `scripts/commons-search.mjs`.

## Wikidata

У каждой карточки есть ссылка на Wikidata (`links.wikidata`). Идентификаторы легко перепутать, поэтому есть два скрипта:

- `npm run wikidata` сверяет каждый Q-идентификатор с Wikidata по названию и координатам и печатает расхождения.
- `node scripts/find-wikidata.mjs --write` подбирает идентификаторы для карточек, где их нет: ищет по названию, отбрасывает университеты, станции и районы с тем же именем, берёт объект нужного типа рядом с координатами карточки. `--write --all` перезаписывает все, `node scripts/find-wikidata.mjs --write semey` — одну.

Что скрипт предложил, всё равно нужно открыть глазами: у одноимённых сёл и городов он может ошибиться.

## Экспорт в Linked Places Format

`npm run export:lpf` (выполняется и при сборке) создаёт `public/data/toponyms.lpf.json` в формате [Linked Places Format](https://github.com/LinkedPasts/linked-places-format). Это стандарт исторических географических справочников: его принимают [World Historical Gazetteer](https://whgazetteer.org), Pelagios и Recogito. Файл можно загрузить в WHG как датасет, и топонимы Казахстана появятся в международной сети связанных исторических мест. В экспорт попадают все названия с датами и источниками, типы по словарю Getty AAT, координаты, ссылки на Wikidata и этимологии (кроме отвергнутых) как описания.

## Хроника переименований

Вкладка «Хроника переименований» строится автоматически из поля `historical_forms`: каждая смена официального названия становится событием с годом и пояснением из `note`. Клик по событию переставляет ползунок на этот год и открывает карточку. Ссылка на карту может включать год: `/#taraz/1950`.

## Структура

```
data/
  schema.json            схема карточки (JSON Schema)
  sources.yaml           библиография
  toponyms/*.yaml        карточки, по одной на топоним
  raw-kz-admin.osm.json  сырые границы из OpenStreetMap
scripts/
  validate.mjs           проверка карточек
  build-data.mjs         yaml → public/data/toponyms.json
  build-regions.mjs      OSM → границы страны и 20 областей (GeoJSON)
  build-photos.mjs       Викисклад → public/data/photos/<id>.json
  check-wikidata.mjs     сверка Q-идентификаторов с Wikidata
  find-wikidata.mjs      подбор Q-идентификаторов по названию и координатам
  export-lpf.mjs         экспорт в Linked Places Format (World Historical Gazetteer)
  commons-search.mjs     поиск категорий и файлов на Викискладе (CLI и библиотека)
public/data/             собранные данные для карты
src/main.js              карта (MapLibre GL), панель, карточка, ползунок времени
```

## Карта

- Подложка: OpenFreeMap (стиль positron), без ключей и лимитов.
- Границы Казахстана и 20 регионов (17 областей и 3 города республиканского значения) из OpenStreetMap, актуальные на 2026 год. Обновить: `npm run regions` после свежей выгрузки в `data/raw-kz-admin.osm.json`.
- Ползунок года показывает название, действовавшее в этот год. Населённые пункты, ещё не основанные к этому году, скрываются; реки и горы остаются.
- Ссылка `#id` открывает карточку напрямую, например `/#taraz`.
